EUSEE Dashboard

A role-aware monitoring and analytical platform for exploring civic-space alerts through summary indicators, interactive charts, relationship analysis, geospatial views, filtered exports, embedded documentation, and an AI copilot.

Purpose

The application converts a curated alert dataset into an executive and analytical decision-support interface while preserving access control at tab, module, chart, map, table, export, and AI-copilot levels.

Interpretation principle: dashboard outputs represent reported monitoring evidence. They should not be interpreted as population prevalence estimates without contextual review and partner validation.

Core capabilities

Role-aware tabs

Overview, Negative Alerts Analysis, Visualization Map, and User Manual are dynamically exposed through permissions.

Secure authentication

Firebase email authentication, verification, token refresh, browser cookies, and persistent sessions.

Granular authorization

Feature- and chart-level permissions are resolved through the external authorization layer.

Interactive analytics

Plotly bar charts, stacked bars, heatmaps, Sankey flows, maps, summary cards, and responsive chart layouts.

Advanced filtering

Region, country, alert attributes, enabling principles, year/month, and Boolean table search.

Data exports

Filtered records can be exported to Excel; PDF quick-start and full manuals can be downloaded.

AI copilot

LangFlow-backed question answering and plot generation use the active filtered dashboard context.

User-specific history

Copilot history is persisted per verified user and restored after refresh.

Responsive UX

Custom Streamlit CSS supports desktop, tablet, and mobile layouts with compact controls.

Deployment resilience

Cached data/PDF loading, safe fallbacks, error messaging, and Docker-aware export paths.

Authentication and security model

  • Firebase provides registration, login, password reset, email verification, ID tokens, and refresh tokens.
  • The browser-specific cookie is named eusee_auth_session and is configured for a 30-day lifetime.
  • Token restoration occurs before the dashboard renders; invalid cookie payloads are deleted.
  • Chat histories are separated by a SHA-256-derived user key and capped at 80 messages.
  • Authorization is distinct from authentication: authz.py is expected to determine roles, permissions, and row-level data scope.
  • Streamlit source/deploy controls and GitHub links are hidden in the interface, but this is a UX measure—not a security boundary.
Production hardening: use HTTPS, restrict secret-file permissions, place persistent histories on protected storage, rotate Firebase/LangFlow credentials, and avoid storing raw refresh tokens in logs or analytics.

Data loading and transformation

  1. Resolve /exportsexports/ folder.
  2. Read output_final.parquet with a one-hour Streamlit data cache.
  3. Validate required alert columns and create safe empty fallbacks where necessary.
  4. Read countries_metadata.json, normalize country names, map ISO-3 codes and continents, then derive dashboard regions.
  5. Remove non-alert event rows and invalid impact/country records.
  6. Parse creation_date, derive year/month fields, and expose the latest dataset date.
  7. Apply role-specific row-level scope through apply_data_scope().

Deployment and operations

Docker considerations

Mount the current export bundle at /exports and mount the configured chat-history directory to persistent storage. Ensure the Streamlit process can read PDFs and metadata and write histories.

docker run --rm -p 8501:8501 \
  -v /host/exports:/exports:ro \
  -v /host/chat-history:/app/.eusee_chat_history \
  --env-file .env \
  eusee-dashboard:latest
Health checks

Monitor the Streamlit endpoint, container restart count, Parquet modification date, Firebase token-refresh failures, LangFlow response codes, and write access to the history volume.

Cache behavior

Dataset and PDF bytes are cached for one hour. Clear Streamlit cache or restart the process when an urgent data/document update must become immediately visible.

Release checklist
  • Validate the Parquet schema and date coverage.
  • Verify country metadata completeness and inspect missing ISO warnings.
  • Test guest, viewer, privileged, and admin roles in separate browsers.
  • Test refresh persistence, logout, email verification, password reset, and token renewal.
  • Confirm each permission hides or reveals the correct tab/module/chart.
  • Validate mobile layout, Excel exports, manuals, map, Sankey, and copilot.

Troubleshooting

Login state is shared between users or devices

Do not store identity in process-global variables, cached functions, or server-wide singleton payloads. The CookieManager object may be singleton, but the cookie value must come from each browser. Confirm that role/email resolution is session-based and that no authenticated state is decorated with @st.cache_data or @st.cache_resource.

User is logged out after browser refresh

Check that the cookie is actually committed before rerun, the refresh token is included, Firebase’s secure-token endpoint is reachable, and restore_session() executes before gated rendering. Verify browser cookie policies and HTTPS/SameSite behavior in the hosting environment.

Duplicate Streamlit component key

Create only one CookieManager instance with the fixed key eusee_cookie_manager_main. Avoid constructing it inside repeatedly called or cached functions.

Dashboard stops at “Restoring secure session…”

Ensure st.session_state.restored is set on every normal exit path, including logged-out browsers and temporary token-refresh failures.

Parquet file not found

Confirm the file is named exactly output_final.parquet and is located in /exports for Docker deployments or exports/ for local execution.

Missing ISO codes

Add or correct entries in countries_metadata.json, or extend the country-name normalization dictionary. Review spelling, accents, Congo variants, and legacy country labels.

Copilot returns 400/403/413 errors

Verify the LangFlow URL/key, request schema, endpoint authorization, and payload size. Reduce dashboard context or top-N lookup content for 413 responses.
